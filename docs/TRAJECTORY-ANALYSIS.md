# 三种来源的鼠标轨迹：官方实现核对

核对日期：2026-10-16。结论来自固定样本的静态分析；没有运行 Windows EXE、刷写固件、向设备发送命令或改变正在运行的 YOLO/监控会话。

## 结论

官方 Windows **NetHost 20260904** 的监控绘图只有一路累计 XY。**NB 20260903 固件内置的轨迹页面**确实区分物理鼠标、软件直通移动和盒内修正步骤，以绿、红、黄三种颜色绘制。两者不是同一个数据接口。

NB 的实现是**同一画布、共享累计坐标、按事件来源给线段着色**。不能把它描述成三个独立累计坐标的完整曲线，也不能据此保证每次移动同时产生三份数据。官方说明中，红色对应关闭硬件曲线后的软件输入，黄色对应开启修正后的输出；本次看到的直接发送与修正调用路径也有此区别。[NB 轨迹说明](https://www.kmbox.top/wiki_doc/kmboxNB/site/022-Trace/)

普通网络监控并不读取这个内部轨迹队列。仅移植 Windows 绘图或增加三个图表，无法补出盒内修正过程。

## Windows NetHost 的实际路径

地址相对于 EXE 镜像基址 `0x140000000`：

| 位置 | 行为 |
| --- | --- |
| `0x1400079A0` | 开启监控，订阅端口 6688，启动接收/绘图流程。 |
| `0x140002C00` | 接收后只取鼠标 8 字节与键盘 12 字节；没有三种来源的字段解析。 |
| `0x140004A50` | 从最新鼠标快照提取位移，写入一个鼠标环形队列。 |
| `0x140006D20` | 从该队列累计一组 XY，用一个红色画笔画线。 |
| `0x140003570` | “清空网络鼠标轨迹”按钮的处理函数只有返回，没有第二路清空实现。 |

“曲线轨迹测试”按钮实际指向芯片 ID 查询，也不是三路轨迹采集。不能根据按钮标题推定功能已完成。

[Net 手册](https://www.kmbox.top/wiki_doc/kmboxNet/site/)确实称其可显示包含第三方输入的最终运动。这个描述适用于其说明的 Net 行为；没有来源标记的单路数值不能证明每个 NB 固件也以同一采样位置上报，更不能分离三路。

## NB 盒内三色轨迹的实际路径

| 来源 | 入队函数 | 类型 / 颜色 | 已追到的生产位置 |
| --- | --- | --- | --- |
| 物理鼠标 | `0x4008E390` | 1 / 绿，RGB565 `0x07E0` | USB 输入回调，例如 `0x40047140`。 |
| 软件直通移动 | `0x4008E1F0` | 2 / 红，`0xF800` | 软件移动直接发送分支，例如调用点 `0x40095676`。 |
| 盒内修正步骤 | `0x4008E2C0` | 3 / 黄，`0xFFE0` | 修正步进函数 `0x40091590`，在 `0x400916CC` 入队，随后调用鼠标发送函数。 |

三处都写入 `0x401E0038` 开始的同一个环形缓冲，容量 8192 项，每项占 6 字节：

| 偏移 | 内部格式 |
| --- | --- |
| 0 | 来源标签低 7 位；高位用于新一段轨迹的标记。 |
| 1 | 本次检查的读写路径未使用。 |
| 2–3 | 有符号 16 位相对 X。 |
| 4–5 | 有符号 16 位相对 Y。 |

这是**固件内部结构，不是已公开的网络报文格式**。索引经过三倍后左移一位，对应 6 字节步长；类型使用 `th.srb` 写入一个字节，`th.lrbu` 读取。队列读函数为 `0x4008E480`。

页面初始化 `0x40032380` 启动名为 `TraceView` 的绘图线程，入口 `0x400320F0`。它读取事件、提取来源、缩放位移、累计坐标并按来源选色画线。三种来源共用 `0x40185A3C/0x40185A40` 的浮点 XY，以及 `0x4017CF70/+4` 的前一绘制位置。高位标记会触发清屏并重新从中心开始；写入端在距离上次事件超过 500 个系统计时单位时设置该位，尚未核实该单位是否为毫秒。

黄色数据来自实际修正步骤，不能拿客户端 Bézier 预览或命令终点代替。是否产生修正仍受算法、阈值和显示条件影响；本次没有恢复完整阈值判定公式，也没有读取用户盒子的当前阈值。内部记录位于发送调用前，单凭该记录也不能证明目标电脑已经接收对应 USB 输入。

## 为什么 Mac 的普通监控拿不到这三种来源

NB 样本的网络发送函数 `0x40095020` 从鼠标缓存 `0x401F5320/0x401F5328`、键盘缓存 `0x401F52D8/0x401F52E0` 拼成 20 字节再发送。已追到的 USB 回调先更新这些输入缓存，再分别调用物理轨迹入队和网络上报。该发送函数不读取上述带来源标签的轨迹队列。

因此，这一普通监控链与盒内三色绘图的数据契约不同。本次未找到可供 Mac 订阅的带来源轨迹导出接口；这不是对所有固件、所有未知命令均不存在接口的证明。

同时，`0x40094F50` 在开启监控前关闭旧监控 socket，并覆盖唯一保存的目标地址/端口；停止函数 `0x40094F00` 关闭这一路。这支持当前观察到的订阅互抢：Mac 开启监控后，依赖盒子按键上报的另一程序可能收不到触发键，但普通鼠标命令仍能发送。此结论针对所分析 NB 样本，不能推广为所有型号只允许一个控制客户端。

## 对 Mac 实现的要求

- 程序输入可以从实际发送方记录，或在能够观察其网络报文的位置采集；只记录 KMBox Mac 自己发送的终点看不到 YOLO 发出的命令。
- 共享现有监控接收器并分发报告，或采用被动报文采集，可以避免第二次订阅覆盖 YOLO。二者不会把普通 20 字节报告变成带来源的盒内修正记录。
- 要忠实复现盒内三色显示，需要确认并使用固件导出接口，或新增导出带类型/序号/时间的内部事件能力。另一种研究方向是采集真正的 USB 输出，但那是输出观测，还需要对齐输入并验证合并后的来源，不能自动等价为三个独立来源。

本次完成的是静态调用链、颜色映射和格式核对。真实 Windows 使用流程、用户当前固件、第三方输入与阈值触发后的完整三路观测均未在本次验证；应用行为未修改。
