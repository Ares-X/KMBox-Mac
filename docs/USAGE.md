# 使用指南

[返回 README](../README.md) · [型号兼容性](COMPATIBILITY.md) · CLI 全部参数：`kmctl --help`

## 网络连接

1. 为盒子供电并按型号接线；Net 控制输出到 OTG 端连接的电脑。
2. Mac 能访问盒子所在网络后，在“网络控制”填入盒子屏幕或设备设置中的 IP、端口、UUID。应用不会扫描或修改网络配置。
3. 多网卡时选择实际连接盒子的本机 IPv4。点击“连接设备”；收到匹配握手才显示已连接。
4. 连接后自动查询外设信息。查询失败或全零不会关闭已经有效的控制连接，也不会作为有效解析参数显示。

重复连接不是无副作用的诊断。其他程序可能改写盒子的会话或监控目标，多客户端能否同时工作由型号和固件决定；测试时应协调设备控制程序。

### 鼠标与键盘

方向按钮使用即时相对移动。X/Y 输入区可选择即时、自动、Bézier：X/Y 是相对终点，P1/P2 是同一起点下的相对控制点。定时移动请求为 1–10000 ms，坐标为 -32768…32767。该时间上限让客户端通信等待有界，不是固件能力上限声明。

自动/Bézier 是单次移动命令，不配置盒内 AI 算法。收到 ACK 不能证明真实运动时长或形状。轨迹图中的“本程序发送轨迹”只连接获 ACK 的请求终点，不产生假中间点。

键盘使用 USB HID 编码，例如 A=4、W=26；不是字符编码。支持修饰键和最多 10 个普通按键。保持按下后可单独释放，或用“全部释放”/⌘Esc。超时可能表示指令已经执行但 ACK 丢失，程序不自动重发相对移动；显式释放可恢复输入状态。没有已确认的中途取消盒内定时移动命令。

## 配置与监控

解析模式写入前读取外设标识，写入后再回读。其他配置项（IP/端口、VID/PID、原 Net 曲线、KM/Bypass）目前只有写入 ACK，不具备已确认的当前值读取；输入框是待写入草稿。

IP/端口改变通常需重新上电；模式写入与重启是两个操作。VID/PID 需要在 OTG 电脑重新枚举后验证。外设信息是接入盒子的外设标识，不能替代 OTG 标识验证。

监控先绑定所选 Mac 接口的接收端口，再通知设备上报。默认端口 6688，可选 1024–49151。只解析来自指定设备的标准 20 字节报告；未知长度保留原始数据，不绘制。开始监控可能改变盒子的上报目标；断开或退出会尝试停止本连接发起的监控。停止 ACK 丢失会显示未确认。

- GUI 保留最近 10000 条记录，同时限制原始字节量不超过 8 MiB，显示淘汰数。成功开启新的本机接收后清空旧缓存；停止/断开仍可导出，退出应用前应保存需要的记录。
- “导出原始记录”保存 JSONL：原文、Mac 双时钟、来源、会话/接收序号和解码结果。时间戳不是设备执行时间。
- CLI `monitor ... --monitor-output 新文件.jsonl` 按批次持续写入；不覆盖已有文件，中断保留部分日志。UDP/系统缓冲丢包无法由主机接收序号推算。
- Net 应答统计只统计实际事务；RTT 包括设备处理时间。清空不发探测，新连接重新计数，断开保留统计。超时计数不等于实际链路丢包。

NB AI 目录/当前值/阈值及三路来源读取仍未实现。原 Net 的四项曲线位于兼容折叠区，不代表 NB 算法列表。

## Python 工作台

1. 在兼容固件中启用 B 串口 / Python，Mac 出现对应 `/dev/cu.*` 后选择端口，默认 115200。
2. 点击连接会发送 Ctrl-C 中断当前脚本，再进入 raw REPL。程序不通过 DTR/RTS 或自动软重启复位设备。
3. 打开本地文件或浏览板载目录，编辑后“运行”直接执行编辑区代码。“上传并运行”先传文件、读回核对，再执行板载文件。
4. 终端支持表达式、命令历史和实时输出；脚本等待 `input()` 时可发送一行文本。“停止”发送 Ctrl-C 并等待回到解释器。
5. 库文件可作为普通 `.py` 文件上传。板载 `km` 模块由固件提供；本应用不实现或替换它。

连接状态下语法检查使用设备的 `compile()`，不执行代码；离线检查调用已安装的 Python 3，不证明 MicroPython 兼容性。GBK/GB18030 和 UTF-16 可显式打开并转为 UTF-8，执行前处理 BOM 并更新编码声明。单文件上限 1 MiB，CLI 也支持二进制上传/下载。

### 文件保护和恢复

本地保存检查文件是否被其他程序改变；上传使用临时文件、读回验证、原文件备份和替换前的基线检查。成功替换后保留 `.kmbak-…` 备份。上传失败不会自动清理证据或重试：重新连接后检查目标、`.kmupload-…` 和备份，先下载备份再决定恢复。

“设为启动脚本”生成当前 REPL 目录的 `main.py` 入口并保留备份；是否上电运行取决于固件与 Python 开关。普通保存、会话恢复不自动上传或执行。

草稿保存在 `~/Library/Application Support/KMBoxMac/session.json`，包含编辑内容和冲突检测基线。设置初始化保留草稿。文档菜单还支持查找/替换、注释、缩进、本地工作区和拖入文件。

| 操作 | 快捷键 |
| --- | --- |
| 新建 / 打开 / 保存 | ⌘N / ⌘O / ⌘S |
| 工作区 / 另存为 | ⇧⌘O / ⇧⌘S |
| 查找替换 / 语法检查 | ⌘F / ⌘B |
| 运行 / 上传并运行 | ⌘R / ⇧⌘R |
| 停止脚本 / 释放键鼠 | ⌘. / ⌘Esc |
| 注释 / 增减缩进 | ⌘/ / ⌘] / ⌘[ |

## 固件下载服务

只实现 NB 官方通用 Web 更新路径。自行从[官方 NB 固件页](https://www.kmbox.top/NB_firmware.html)取得正确 `.cpio`，备份需要的脚本/配置后，在“固件与兼容性”选择文件与 Mac 的设备网络接口，启动默认 TCP 80 服务。可选填写来源设备 IP 以限制访问。

在盒子升级页填写 **Mac 地址**，由设备请求 `/kmboxNB.cpio`，自行写 Flash 和重启。保持供电与网络。服务固定所选文件快照，不提供目录浏览；端口占用或系统拒绝时报告失败，不自动改端口来冒充兼容。

CPIO 校验不是数字签名验证，传输完毕也不是刷写成功。无法进入升级页的设备不适用此恢复方式。其他型号不能套用 NB 固件或流程；本仓库不提供厂商固件。

```bash
./dist/kmctl firmware-check /path/to/NB.cpio
./dist/kmctl --local MAC_IPV4 --host DEVICE_IP firmware-serve /path/to/NB.cpio
```

## 采集与截图

选择系统实际枚举的采集卡/相机、格式和帧率后启动预览。首次需 macOS 相机权限。支持 PNG/JPEG/BMP/TIFF；可绑定设备监控中的左键按下事件截图。没有收到设备报告时，不能据此触发截图。真实采集卡全链路仍需验证，未实现原工具的 MP4 占位功能。

## 数据与权限

连接信息存于本机偏好，草稿存于用户 Application Support，截图与日志由用户选择路径。监控可包含键鼠输入，应在分享前脱敏。应用不自动上传日志或草稿。

厂商在线适配使用原工具内置的普通 TCP 服务 `47.75.195.35:5002`。查询发送外设 VID/PID/Device ID/HID ID；主动反馈还发送解析模式与测试结果。界面相应按钮才触发，连接、读取本地配置不会自动提交。该厂商服务不由本项目维护，真实可用性未验证。

视频使用系统相机权限；Net/HTTP 使用本地网络；用户自选的串口和文件按当前用户权限访问。程序没有提权助手，不修改防火墙或系统路由。

## 无设备体验

```bash
mkdir -p artifacts
python3 tools/mock_nb.py --info artifacts/mock-info.json --root artifacts/mock-board --log artifacts/mock-events.jsonl
```

保持模拟器运行，把输出的回环地址/端口/UUID 或 PTY 路径填入应用。也可用启动参数 `--temporary-session --host=127.0.0.1 --port=模拟端口 --uuid=模拟UUID --local=127.0.0.1 --page=diagnostics`。临时会话不覆盖正常配置/草稿。启动参数使用等号以避免 macOS 把值解释为打开文件。

模拟器仅执行可信测试脚本；其本机 CPython 环境不是隔离沙箱，也不等同于 NB 固件。
