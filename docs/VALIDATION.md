# 验证说明

## 证据层级

- **代码测试**：验证编码、解析、状态和失败路径，不表示设备固件支持。
- **本机集成/GUI**：使用真实回环 UDP、PTY 及打包应用；模拟板使用 CPython，不等同于设备 MicroPython。
- **实际设备观察**：需要具体型号、固件、接线和实际 OTG 输出。ACK、传输进度或相机枚举不能代替最终行为。

## 1.3.2 轨迹与接收状态

2026-10-15 至 16 日，在 Apple Silicon、macOS 27.0.1、Swift 6.4 环境，NB 通过 USB 网络连接 Mac。纠正目标 IP 并使用对应本机接口后，1.3.1 CLI 在 30 秒内收到 4457 条报文，其中 4429 条包含非零鼠标位移，全部长度 20 字节；监控开启和停止均获得应答。本次真实报告在修改解析器前已经收到，不能把允许附加字节的修改描述为实机故障根因。设备固件版本未读取。

1.3.2 新增前缀解析、完整原文长度与收包分类、监听地址和接收状态，并按批次更新位移图。新增测试覆盖附加字节、短包、零长度 UDP、其他来源、空闲无假数据、停止／重启、清空图形保留记录，以及模型经真实回环 socket 收包绘图。

打包 GUI 已在同一 NB 收到 5202 条报告，实际显示设备轨迹；用户操作还生成了独立的本程序请求终点图。停止后保留图形与记录，GUI 导出 JSONL 经核对为 5202 条连续接收序号、全部 20 字节。重新开始监控会重置记录和设备轨迹，无报告时显示等待。不能从这次混合操作推断三路来源或盒内修正采样位置。

75 项 Swift 测试、83 个发布 CLI 场景通过，arm64/x86_64 通用应用构建和严格 ad-hoc 签名通过。图形清空保留原文、错误后停止及重启的状态由模型测试覆盖。

实窗检查也发现一次点击连接后因 `SIGPIPE` 退出，系统日志已保留。网络 socket 现在使用 `SO_NOSIGPIPE`，让失效 socket 的 `EPIPE` 进入既有发送错误处理；不全局忽略信号、不重试输入。更新后的实窗首次连接也返回了 `Broken pipe`，应用保持运行并显示错误；同期 `nehelper` 记录已允许本地网络，但需要清除旧 UUID 缓存并重新建立权限会话。该日志支持应用更新时的系统缓存变化，尚不足以证明所有 `EPIPE` 都由此引起。旧构建随后自动及指定接口均曾成功连接。

隔离故障对照通过：对同一回环首发执行 `shutdown(SHUT_WR)`，旧 CLI 被信号 13 结束；新 CLI 正常退出码 1 并报告 `Broken pipe`。该场景已加入 `tools/verify_cli.py`，通过 Xcode 自带 Clang 构建仅用于子进程的测试动态库；同一回归检查能拒绝旧二进制。故障测试没有向实机发送数据，也没有全局屏蔽信号。

## 从干净源码复现

```bash
swift test
python3 tools/verify_cli.py .build/debug/kmctl
bash scripts/build-app.sh
python3 tools/verify_cli.py dist/kmctl
codesign --verify --deep --strict "dist/KMBox Mac.app"
```

测试使用临时目录、回环端口、PTY 和仅注入测试子进程的发送故障夹具，不需要 `research/`、厂商固件、真实盒子或第三方 Swift 包。Python 3 标准库需可用；PTY 测试使用 `/usr/bin/python3`。这些命令应在仓库根目录运行。

可选固件传输检查：`python3 tools/verify_firmware.py dist/kmctl /path/to/official.cpio 80`。这个额外工具需要自备文件、空闲本机端口及第二个有效 IPv4 以测试地址过滤；它只在本机请求，不刷设备。通用 `swift test` 已使用合成 CPIO，不需要下载固件。
